# Dummy Studio (ต้นแบบ 0.1)

โปรแกรม Windows หน้าตาแบบ Godot สำหรับจัดการข้อมูลเกม Dummy Online โดยไม่ต้องแก้ไฟล์ด้วยมือ
ใช้ Electron — แตกโฟลเดอร์นี้ไว้ที่ `studio/` ในรากของ repo

## ทำอะไรได้ตอนนี้
- **FileSystem**: เรียกดู/แก้ไฟล์ข้อความ (JSON/config) และดูรูปทั้งโปรเจกต์
- **Resources**: ตัวละคร, ไอเทม (ธีม โต๊ะ พื้นหลัง ไพ่ แถบปุ่ม หลังไพ่ กรอบ), ตู้กาชา, ไฟล์ตั้งค่า (ร้าน/กาชา/UI/เสียง)
- **Inspector**: ฟอร์มสร้างอัตโนมัติจาก config (ตัวเลข สี ตัวเลือก รายการเพิ่ม/ลบได้) · Ctrl+S บันทึก
- **Data ▸ ใหม่**: สร้างตัวละคร/ตู้กาชา/ไอเทม · ตัวละครและพื้นหลังใหม่จะถูกเพิ่ม id ใน `CHARS`/`BGS` ของเซิร์ฟเวอร์ให้อัตโนมัติ
- **นำเข้ารูป**: คัดลอกรูปเข้าที่ที่ถูกต้อง (ตัวละคร → `assets-src/Assets/Character/<id>/`) และตั้งชื่อไฟล์ใน config ให้
- **Problems**: ตรวจให้ เช่น ไม่มีรูป, id ไม่อยู่ในเซิร์ฟเวอร์, ตู้กาชา rateUp อ้างของที่ไม่มี, น้ำหนักรวม 0, ตั๋วไม่มีใน economy.js
- **ปุ่มบนขวา**: ▶ Build (`build-assets.js`) · ✔ Check · 🧪 Test (รันเทสต์เซิร์ฟเวอร์ทีละชุด) · 🎮 เกมจำลอง · เมนู Tools สร้าง SQL แคตตาล็อก

## 🎮 เกมจำลอง (F8)
เปิดเกมจริงในหน้าต่างแยกเพื่อดูผลการแก้ข้อมูล เล่นกับบอทได้ครบทุกเกม
- **ออฟไลน์ล้วน**: รันเซิร์ฟเวอร์เกมในเครื่องโดย *ไม่อ่าน* `server/.env` และล้างค่า Supabase ทิ้ง · ปิดระบบบัญชี (เหรียญเก็บในเครื่อง) → ไม่แตะฐานข้อมูลจริง
- **ลำดับ**: แก้ข้อมูล ▸ 💾 บันทึก ▸ ▶ Build → หน้าต่างเกมรีโหลดเอง (เกมอ่าน `skins.json`/`gacha.json` ที่ Build สร้าง)
- ขนาดหน้าต่าง: Tools ▸ เกมจำลอง · มือถือแนวนอน (844×390) หรือ · จอคอม (1280×720)
- ในหน้าต่างเกม: **F5** รีโหลด · **F12** เปิดเครื่องมือดู error
- รูปตัวละครแสดงจากต้นฉบับใน `assets-src/` (ใช้โหมดพัฒนาของ `pack-loader.js` — ไม่ถอดรหัสแพ็ก) จึงเห็นรูปที่เพิ่งนำเข้าได้ทันทีโดยไม่ต้องรอ GitHub Actions
- ครั้งแรกต้องกด Tools ▸ ติดตั้งแพ็กเกจเซิร์ฟเวอร์ (npm install) ก่อน
- ข้อจำกัด: ไม่มีล็อกอิน/กาชา/แรงก์แบบบัญชี (ต้องใช้ฐานข้อมูลจริง) · ฟอนต์และ socket.io ยังโหลดจากอินเทอร์เน็ต

## รันบน Windows
ต้องมี [Node.js 20+](https://nodejs.org)
```
cd studio
npm install
npm start
```
เปิดโปรแกรมแล้วกด **เปิดโฟลเดอร์โปรเจกต์** เลือกรากของ repo Dummy-Online

## สร้างไฟล์ติดตั้ง .exe
ทางที่ง่ายสุด: คัดลอก `.github/workflows/studio-win.yml` ไปไว้ใน repo → push → ใน GitHub ไปที่ Actions ▸ *Build Dummy Studio (Windows)* ▸ Run workflow → ดาวน์โหลด artifact `DummyStudio-win`
หรือในเครื่อง: `npm run dist` (ผลลัพธ์อยู่ใน `studio/dist/`)

## ทดสอบ
```
npm test                                   # แกนข้อมูล (ตั้ง DUMMY_ROOT เป็นรากโปรเจกต์)
node test/test-runner.js <รากโปรเจกต์>      # ตัวรัน build/check/test
node test/test-preview.js <รากโปรเจกต์>     # เกมจำลอง (ต้อง npm install ใน server ของโปรเจกต์ก่อน)
node test/ui-smoke.js <รากโปรเจกต์>         # หน้าต่างจริงในเบราว์เซอร์ (ต้องมี playwright)
```
ชุดทดสอบทำงานบนสำเนาชั่วคราว ไม่แตะโปรเจกต์จริง

## ความปลอดภัย
- หน้าต่างไม่เข้าถึง Node โดยตรง (contextIsolation) — คุยกับระบบผ่านคำสั่งที่ประกาศใน `preload.js` เท่านั้น
- ทุกการอ่าน/เขียนถูกจำกัดอยู่ในโฟลเดอร์โปรเจกต์ · ไม่เซฟ JSON ที่พัง · ไม่เก็บ/ใช้กุญแจ Supabase ใด ๆ
- ราคา/เรตกาชาที่แก้ในนี้เป็นแค่ไฟล์ — ต้องรัน **Tools ▸ สร้าง SQL** แล้ววางใน Supabase เองเหมือนเดิม

## ยังไม่มี (ลำดับถัดไป)
1. Playground (ให้บอทเล่นกันหลายพันตาแล้วสรุปสถิติ)
2. Scene editor ลากวางหน้าจอ/ป้าย/ปุ่ม (ต้องแยกหน้าใน `app.js` เป็นข้อมูลก่อน)
3. ตัวแก้กฎเกมแบบฟอร์ม · แก้สกิลใน `skills.json` · ลบ/ทำสำเนา resource

> หมายเหตุ: ต้นแบบนี้ทดสอบ logic และหน้าต่างในเบราว์เซอร์จริง (Chromium) บน Linux เท่านั้น ยังไม่เคยรันเป็นแอป Electron บน Windows — ถ้าเปิดแล้วติดปัญหา ส่งข้อความ error มาแก้ต่อได้
